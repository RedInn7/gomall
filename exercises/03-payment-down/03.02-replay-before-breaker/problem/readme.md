# 熔断时仍然回放成功支付

## 故障现场

支付数据库连续超时，熔断器已经打开。此时有两个请求到达：

1. 用户第一次发起一笔新支付；
2. 另一位用户重试一笔数据库早已提交、成功响应也已保存的支付。

新请求应该被熔断器拒绝，避免继续冲击数据库；已完成请求不需要访问数据库，应直接回放。如果先检查熔断器，第二位用户会看到“支付失败”，甚至继续换渠道重试。

## 任务

补全 `Handle`，执行顺序必须是：先检查幂等成功结果，再检查熔断器，最后调用支付函数。

## 业务规则

- 已有成功响应：直接返回，不调用 `pay`；
- 没有成功响应且熔断器 Open：返回 `ErrCircuitOpen`；
- 支付成功：保存响应；
- `BusinessError`（如余额不足）不增加熔断失败次数；
- `SystemError`（如数据库超时）增加熔断失败次数；
- 失败响应不进入成功缓存。
