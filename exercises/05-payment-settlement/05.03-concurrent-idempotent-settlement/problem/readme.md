# 05.03：六十四个重复事件只能给卖家放一次款

## 故障现场

消息队列因超时同时重投同一订单。多个 worker 都在旧快照里看到 `cleared`，随后各自给卖家加钱。另一些订单同时结算到同一个卖家，又因为读改写竞争丢失了一部分余额。

## 任务

完成线程安全的 `Store.Settle`。同一订单 64 路并发调用必须只入账一次，不同订单同时结算到同一卖家也不能丢失更新。

## 业务规则

1. 状态检查、托管扣款、卖家加款、流水追加和状态推进必须处在同一临界区。
2. `settled` 是幂等终态，重复调用返回成功。
3. 未知订单、非法记录或余额不足必须拒绝且零写入。
4. 不能只给 map 写操作加锁；“先检查再写入”的整个过程必须串行化。
5. `Snapshot` 也必须同步并返回副本，测试和监控读取不能制造数据竞争。
